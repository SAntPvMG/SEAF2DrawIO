# Intrinsic: горизонтальные ряды LAN при большом числе полосок

> **Актуальное требование (2026-05):** вертикальные **колонки** до **`deep + 3`** полосок, следующая колонка с того же верха, шаг **`offset × 2`** — см. **[lan-vertical-columns-layout-spec.md](lan-vertical-columns-layout-spec.md)**. Документ ниже описывает уже реализованную схему «одна полоса по Y, LAN вдоль X», которая **не совпадает** с этим требованием и подлежит замене в коде.

## Правило (из требований)

Параметры берутся из паттерна **`lan`** в `data/patterns/dc.yaml` и `data/patterns/office.yaml`:

1. Если число объектов LAN в сегменте **больше**, чем **`lan.deep`**, располагать LAN **по горизонтали** группами по **`deep + 3`** штук в каждой группе (первая группа начинается с той же логики по X, что и сейчас: от `INT_SEGMENT_GAP_LEFT` с учётом left/right колонок каждой LAN).
2. Если LAN **больше**, чем **`deep + 3`**, следующие объекты идут **в новой горизонтальной группе**:
   - **та же верхняя координата (Y)**, что и у первой группы — все группы выровнены **по верху в одной горизонтальной полосе** сегмента (один общий `cur_y` / одна «полка» по высоте);
   - **расстояние `lan.offset * 2`** относят к **промежутку по горизонтали** между концом предыдущей группы (правый край занятой области последней LAN и её правой колонки) и началом следующей группы (перед первой LAN следующей тройки/семёрки).
3. Пока LAN не закончатся — повторять: снова до **`deep + 3`** по X в той же полосе Y, перед следующей порцией снова зазор **`offset × 2`**.

Итоговая геометрия в этом режиме: **одна горизонтальная линия размещения по Y**, по **X** — последовательность блоков «до deep+3 LAN», затем **gap `offset×2`**, затем снова «до deep+3 LAN», и т.д.

Пример при `deep: 4`, `offset: 100` (в группе до **7** LAN):

- LAN ≤ `deep` — **без** этого режима: как сейчас intrinsic (**вертикальная** склейка рядов с `gap_uniform`).
- LAN > `deep` — все LAN идут **в одной горизонтальной полосе по Y**; первые **7** — подряд по X; если есть **8-я** и далее — после правого края 7-й группы промежуток **200 px**, затем следующие до **7** по X при **том же верхнем Y**, и т.д.

Высота полосы (`band_h`) в этом режиме — **`max(row_h)` по всем LAN сегмента**, чтобы все полоски и их left/right колонки помещались по вертикали без смещения «полки».

**Отступ первой группы от верха сегмента — как раньше через `gap_uniform`:** контент не прижимается к `INT_SEGMENT_GAP_TOP`. Считать по той же схеме, что и в текущем intrinsic, но для **одной** вертикальной полосы высотой `band_h`:

- `inner_avail_h = base_h - INT_SEGMENT_GAP_TOP - INT_SEGMENT_GAP_BOTTOM`
- `sum_row_h = band_h`
- для расчёта зазора взять **`n_rows = 1`** (одна логическая «полка» по вертикали)
- если `inner_avail_h - sum_row_h >= 0`: `gap_uniform = (inner_avail_h - sum_row_h) / (n_rows + 1)` → **`(inner_avail_h - band_h) / 2`**
- иначе: `gap_uniform = SEGMENT_GAP` (как в коде при нехватке бюджета)
- **`cur_y = INT_SEGMENT_GAP_TOP + gap_uniform`** — верх первой группы LAN и их колонок; все горизонтальные группы по X остаются на этом же **`cur_y`**.

Так вертикальное размещение полосы внутри шаблонной высоты сегмента согласовано со старым режимом при том же `band_h`.

## Место реализации

Файл: **`auto_layout/segment_intrinsic_layout.py`**, функция **`compute_intrinsic_band_layout`**, блок после формирования **`row_specs`** и **`spec_by_lan`**.

## Что менять в коде

1. **Ключ кэша** intrinsic: суффикс обновить (например `'v23-lan-horizontal-same-y'`).

2. После **`spec_by_lan`**, параметры из **`lan_pat`**: `lan_deep`, `offset`, **`max_lans_group = lan_deep + 3`**, **`horizontal_group_gap = offset * 2`**, **`use_horizontal_lan_bands = len(row_specs) > lan_deep`**.

3. **Если `use_horizontal_lan_bands`**:

   - **`band_h = max(s['row_h'] for s in row_specs)`**.
   - **`gap_uniform`**: как для одного вертикального ряда высотой **`band_h`** — **`n_rows = 1`**, **`sum_row_h = band_h`**, **`inner_avail_h`**, затем **`cur_y = INT_SEGMENT_GAP_TOP + gap_uniform`** (см. раздел про отступ сверху).
   - **`x_cell = INT_SEGMENT_GAP_LEFT`**, **`temp_lan_right_edge`**, счётчик **`idx`** по порядку `row_specs`.
   - Перед размещением очередной LAN: если **`idx > 0`** и **`idx % max_lans_group == 0`**, выполнить **`x_cell += horizontal_group_gap`**.
   - Разместить текущий **`spec`** (формулы `x_lan`, left/right боксы, якорь `fw_strip_anchor_lan` как в черновике — через **`temp_lan_right_edge`** / **`_intrinsic_row_right_edge_px`**).
   - **`x_cell = row_right_edge + SEGMENT_GAP`**, **`idx += 1`**.
   - **`row_y_start[lan_oid] = cur_y`** для всех LAN одинаковый.
   - Вертикального **`cur_y += …`** между группами **нет**.

4. **Иначе** — сохранить текущее поведение (одна LAN на вертикальный ряд и `gap_uniform`).

5. Проверить **`multi_fw_between`** при нескольких LAN в одной горизонтальной полосе.
