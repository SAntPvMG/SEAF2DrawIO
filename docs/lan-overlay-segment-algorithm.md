# Алгоритм пост-обработки: КБ, ТА, User Devices, LAN и сегменты

Документ фиксирует **целевой** пайплайн для страниц `dc` и `office` после intrinsic-раскладки и добавления объектов паттернами. Общий обзор генератора см. [seaf2drawio-algorithm.md](seaf2drawio-algorithm.md).

## Область применения

- Условие: `file_name in ('dc', 'office')`.
- Выполняется **после** `resize_location_label_to_cover_segments`.
- Зависит от данных `network_connection`, типа сети `LAN`, полей `segment` у сетей и контейнеров `network_segments`.

## Поток (высокий уровень)

```text
intrinsic (positions / segment_size / segment_origin)
    → add_object / паттерны
    → resize_location_label_to_cover_segments
    → kb_layout
    → services_TA_layout
    → user_devices_layout          [целевой модуль]
    → lan_vertical_fit_overlays    [целевой модуль]
    → lan_spread_overlapping_lans    [целевой модуль]
    → lan_segment_align_expand_fit    [целевой модуль]
```

Порядок шагов **не менять** без пересчёта union bbox и пересечений LAN.

---

## Шаг 0. Метка локации

**Функция:** `resize_location_label_to_cover_segments` (`seaf2drawio.py`).

Подгонка подписи ЦОД/офиса над зонами; на геометрию LAN не влияет.

---

## Шаги 1–3. Якорь `network_connection`

Общие правила для КБ, сервисов ТА и User Devices:

1. Поле **`network_connection`** в данных приводится к упорядоченному списку OID.
2. **Якорь** — первый OID из списка, который есть на странице (`diagram_ids`) и проходит фильтр зоны ЦОД (`_pick_anchor_network_oid` в `kb_layout.py`; для офиса фильтр по slug `dc01`/`dc02` в OID может ослабляться).
3. Размещение оверлеев:
   - **Справа** от правой границы bbox якорной сети (`_canvas_bbox_for_oid`).
   - Вертикальное смещение от **верха** якоря — своя константа в каждом модуле.
   - Сетка до **4 элементов в ряд**, шаг между элементами по умолчанию **20 px**.

| Модуль | Слой / родитель | Схема данных |
|--------|-----------------|--------------|
| `kb_layout` | слой Draw.IO **101** | `seaf.company.ta.services.kbs` |
| `services_TA_layout` | слой **102** | `compute_services`, `monitorings`, `backups`, `cluster_virtualizations`, `k8s` |
| `user_devices_layout` | родитель — сеть (не фиксированный слой) | `seaf.company.ta.components.user_devices` |

Реализовано в репозитории: `auto_layout/kb_layout.py`, `auto_layout/services_ta_layout.py`. Модуль User Devices — целевой (см. план работ).

## Шаг 4. Удлинение LAN под оверлеи

**Целевая функция:** `lan_vertical_fit_network_connection_overlays`.

- Для каждой записи сетей с **`type: LAN`**, присутствующей на странице:
  - собирается нижняя граница (max Y) bbox всех оверлеев (КБ + ТА + User Devices), у которых якорь в `network_connection` совпадает с OID этой LAN;
  - оценивается «визуальная» нижняя граница полоски LAN: при `rotation` ≈ 90°/270° длинная сторона на canvas соответствует **`max(width, height)`** в `mxGeometry` (согласовано с шаблоном LAN в `data/patterns/dc.yaml` / `office.yaml`: подстановка `width`/`height`, `rotation=270`).
- Если оверлеи ниже полоски — увеличить размер полоски вдоль длинной оси (часто атрибут `width`) на недостающую дельту плюс небольшой паддинг.

---

## Шаг 5. Разводка пересекающихся LAN

**Целевая функция:** `lan_spread_overlapping_lans`.

- В пределах одного сегмента (`network_segments`): множество LAN по полю `segment` в данных.
- По парам полосок: если усечённые по повороту AABB пересекаются (с зазором), выбирается сдвиг с меньшей величиной — вниз или вправо; двигается одна полоска и **все оверлеи** с тем же якорем-LAN.

---

## Шаг 6. Сегмент: размер и выравнивание LAN

**Целевая функция:** `lan_segment_align_expand_fit` (обычно два прохода на сегмент).

Внутренние поля контейнера задаются константами в `auto_layout/segment_intrinsic_layout.py` (`INT_SEGMENT_GAP_TOP/BOTTOM/LEFT/RIGHT`).

1. **Расширение контейнера сегмента** по объединённому bbox:
   - **полный** контент: все прямые дочерние вершины сегмента в Draw.IO **плюс** оверлеи по якорям LAN в этом сегменте;
   - сравнение с inner-прямоугольником; при нехватке места увеличиваются `width`/`height` контейнера сегмента.
   - Для зоны **`INT-NET`** прирост ширины из union отключается (`WIDE_CENTER_ZONES`), чтобы не раздувать блок без нужды.

2. **Центрирование (второй проход):**
   - центр inner совмещается с центром bbox **только вершин LAN + их оверлеев**;
   - сдвиг применяется к LAN и оверлеям, **не ко всем** потомкам сегмента (роутеры/FW и т.д. не двигаются произвольным центрированием).

3. **Удержание внутри inner (`contain`):**
   - переполнение справа/снизу → ещё рост сегмента по полному union;
   - уход влево/вверх → сдвиг ограниченного набора (LAN + оверлеи); при пустом списке целей — безопасный откат к сдвигу всего контента (защита от зацикливания).

---

## Риски

- Центрирование только LAN+оверлеев может визуально развести полоску от оборудования, если intrinsic жёстко привязал координаты устройств к старым координатам LAN — при регрессии ослабить центрирование или ограничить осью.
- Неверный порядок шагов (например, сегмент до `lan_vertical_fit`) даёт неверные bbox и пересечения.
